# 基建：Node 服务治理

## 背景

Node 服务开发门槛低，但服务一旦进入生产环境，真正决定稳定性的往往不是业务代码，而是超时、重试、日志、优雅下线和资源隔离这些治理能力。

## 核心治理点

- 健康检查：区分存活探针和就绪探针
- 超时控制：接口、数据库、下游请求都要设超时
- 优雅关闭：收到退出信号后先摘流量，再处理完在途请求
- 统一日志：日志格式、链路标识、错误堆栈要统一
- 配置管理：不同环境配置分离，避免把配置写死在代码里

## 运行时建议

- 对外部依赖设置熔断和重试边界
- 限制单请求占用资源，避免拖垮整个进程
- 关键指标接入监控，如 QPS、RT、错误率、内存与事件循环延迟

## 实践结论

Node 服务治理的重点不是“框架选什么”，而是“出问题时能不能快速发现、快速止血、快速恢复”。
