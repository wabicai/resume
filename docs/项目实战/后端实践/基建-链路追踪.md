# 基建：链路追踪

## 为什么需要链路追踪

请求一旦跨越网关、Node 服务、数据库、消息队列，单看一处日志通常无法还原全链路。链路追踪的核心价值，就是把同一次请求的各段耗时串起来。

## 基本概念

- `trace`：一次完整请求链路
- `span`：链路中的一个处理片段
- `traceId`：整条链路唯一标识
- `spanId`：当前节点标识

## 落地重点

- traceId 要在服务间透传
- 数据库、RPC、HTTP 请求都要打 span
- 既要记录错误，也要记录慢请求

## 能解决什么问题

- 到底慢在网关、业务服务还是数据库
- 某次请求失败时卡在哪一段
- 同一问题是否只发生在特定下游

## 结论

链路追踪不是为了“看起来高级”，而是为了在复杂系统里快速缩小排查范围。
