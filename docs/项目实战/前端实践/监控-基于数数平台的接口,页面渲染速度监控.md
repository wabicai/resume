# 监控：基于数数平台的接口与页面渲染速度监控

## 背景

活动页或业务页面一旦变慢，用户感知通常比错误更直接。仅靠线上报错还不够，需要同时监控接口耗时和页面渲染速度，才能尽早发现性能劣化。

## 监控维度

- 接口维度：请求成功率、平均耗时、超时率、异常码分布
- 页面维度：首屏时间、白屏时间、可交互时间、资源加载耗时
- 用户维度：设备型号、网络类型、系统版本、地域分布

## 采集原则

- 指标统一命名，便于横向对比。
- 只采集关键链路，不要把监控本身变成性能负担。
- 接口和页面指标要能通过页面 ID、活动 ID 关联起来。

## 告警建议

- 接口 P95 耗时突增
- 页面首屏时间超过阈值
- 某机型、某网络环境下明显异常
- 同一版本发布后指标回退

## 结论

性能监控真正的价值不在“收集了很多数据”，而在“能用这些数据定位问题并推动回退或修复”。
