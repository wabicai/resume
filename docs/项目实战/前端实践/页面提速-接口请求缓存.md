# 页面提速：接口请求缓存

## 背景

很多页面慢，不是因为渲染逻辑本身复杂，而是因为关键接口每次都重新请求，导致页面首屏被网络耗时拖住。

## 适合缓存的场景

- 短时间内重复访问的数据
- 活动配置、字典、用户弱实时信息
- 多个组件共享但变化不频繁的数据

## 常见方案

- 内存缓存：适合单次会话内复用
- `localStorage` / `IndexedDB`：适合跨页面、跨会话复用
- SWR 风格：先读缓存，再后台刷新

## 设计关键点

- 缓存 key 必须稳定，至少包含接口名和关键参数
- 设置合理的过期时间
- 明确哪些场景必须跳过缓存
- 数据更新后要有失效机制

## 风险

- 缓存脏数据会让页面展示过期内容
- 命中率不高时，缓存层只会增加复杂度
- 缓存逻辑分散在各组件中，会很难维护

## 结论

接口缓存不是无脑加一层，而是围绕“命中率、时效性、失效策略”做取舍。
