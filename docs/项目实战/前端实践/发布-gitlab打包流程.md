# 发布：GitLab 打包流程

## 目标

把“本地打包”升级成“可追踪、可回滚、可审计”的标准发布流程，减少人工操作带来的环境错配和误发布。

## 基本流程

1. 开发分支合并到发布分支。
2. GitLab CI 根据分支或 Tag 触发流水线。
3. 安装依赖、执行测试、构建产物。
4. 产物上传到制品库或部署目标环境。
5. 通过通知渠道回传发布结果。

## 关键控制点

- 环境变量区分测试、预发、生产。
- 构建前先做 lint 和基础校验，避免坏包进入部署阶段。
- 生产环境最好加人工确认，避免误触发。
- 保留历史制品，支持快速回滚。

## 常见问题

- 分支策略不清导致不同环境发布混乱。
- 构建脚本依赖本地环境，CI 上无法复现。
- 配置和代码耦合，切环境容易出错。

## 建议

发布流程的核心不是“能发出去”，而是“任何人都能按同一规则稳定发出去”。
