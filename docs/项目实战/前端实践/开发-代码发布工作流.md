# 开发：代码发布工作流

## 目标

让需求开发、联调、测试、上线、回滚形成一条标准化链路，减少“口口相传”的隐性流程。

## 推荐流程

1. 从主干切需求分支开发。
2. 提交前做自测和基础检查。
3. 发起合并请求，经过 code review。
4. 合并后自动触发测试或预发部署。
5. 验证通过后再发布生产。

## 关键要求

- 提交信息要能说明变更目的。
- 合并前至少保证构建、测试和核心页面可用。
- 发布必须可回滚，不要只保留最新产物。
- 紧急修复与常规需求分支要分开管理。

## 为什么需要工作流

- 便于追踪问题来自哪次发布。
- 缩短排查范围。
- 降低个人经验对流程的依赖。

## 实践建议

真正有效的发布工作流，应该让新人也能按步骤完成，而不是只靠熟手“记得住”。
